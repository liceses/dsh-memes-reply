## 0. 一句话目标（草案）

让 DSH 在**语境合适**时，于 Web GUI 的回复里贴出一张**会动的**蓝色大肥鱼；默认克制——不乱贴、不打断阅读、不拖慢界面，并且可以一键关掉。

## 2. 平台事实（这几条决定了哪些做法可行）

每条都附了证据，你可以复核；**没被我证实的一环我在 F3/路径 D 里单独标出来了**。

### F1 助手消息本体装不了图片
DSH 的图片能力（`dsh-attachment`）是**用户侧**的：README 明确写 assistant-side image output 仍是 forward compatibility，当前生产适配器声明 text-only。所以「让模型返回一个 image block」这条路今天走不通。
证据：`@deepseek-ai/dsh-attachment/README.md`（Dev Note → Future: audio, video, and assistant-side output）

### F2 助手正文里的 markdown 图片**会**渲染，规则是三条分支
前端 markdown 渲染器对 `![](...)` 的目的地这样判定（函数 `jg()`）：

1. 目的是**绝对 http(s) URL** → 直接 `<img>`（`loading=lazy`、`decoding=async`、`referrerPolicy=no-referrer`，失败退化成 alt 文本）；
2. 否则交给 `pathImages.resolve()`：**以单个 `/` 开头的绝对 POSIX 路径** → `http://<origin>/api/file?path=<URL编码>`；
3. 其余（相对路径、`//`、`file:`、`data:`）→ **只渲染 alt 文本，不显示图片**。

另外，流式渲染时 `pathImages` 是 `undefined`，所以**分支 1 在模型还在打字时就能出图**，分支 2 要等这条消息流式结束才出图。
证据：`dsh-web-frontend/dist/assets/index-*.js` 中的 `jg / _g / f5 / kg / v5 / Ig`；`dsh-client-ui-chat/lib/client.js` 中的 `localPathMediaUrl()`。

### F3 `/api/file` 是现成的本地文件通道，但不适合当主力
它要求路径 `isAbsolute`；字节上限 = `attachments.imageLimits.maxImageBytes`（默认 20 MiB）；Content-Type 按扩展名推断；响应头写死 `Cache-Control: private, no-store`；读法是整文件 `readBytes`（**没有 Range**）；并且要过连接服务的鉴权。
证据：`dsh-api-session-controller/lib/types/media-references.js`；本机实测裸 HTTP：`GET /api/file?...` → **401**，`GET /` → **401**。
⚠️ 未能证实的一环：浏览器里的 `<img src="/api/file?...">` 是否带上凭据（cookie）。裸请求 401 只说明它受鉴权保护，不代表浏览器不行——这条通道是官方为「正文里显示本地图片」专门接的线。

### F4 插件**自有**路由不受该鉴权影响，浏览器同源直接可用 ★
这是本项目最关键的可行性事实。
证据：本机实测 `GET http://127.0.0.1:3080/api/dsh-hmm-wait/stats` → **200**，返回 `{"ok":true,"subscribers":1,...}`。该路由由 `dsh-hmm-wait` 用 `ctx.webServer.register({kind:'exact', path, handler})` 注册，浏览器端只 `fetch(path)`，**不带任何 token**；`subscribers:1` 还说明 GUI 页面确实连着它。

### F5 附件流水线会把 GIF **静态化**
走 `ctx.attachments` 的图片会被归一化（≤2048×2048、≤4 MiB、无 alpha 转 JPEG／有 alpha 转 WebP），README 明确写着 *"Animated GIF becomes static — 只保留第一帧"*。
证据：`dsh-attachment-local/README.md`、`dsh-attachment/README.md`。
→ 结论：**只要你想要"会动的鱼"，就不要走附件库。**

### F6 可注入的现成槽位（浏览器侧）
`conversation.message.images`（消息图片组 + 灯箱）、`tool.call.images`（工具卡里的图片组）、`tool.call.toolview`（按工具名自定义工具卡）、`conversation.chat.assistant-actions`（助手消息动作区）、`conversation.chat.turnTail`（一条已结束回复的末尾）、`shell.overlay`（全屏浮层，`dsh-pet`／`dsh-hmm-wait` 都在这里）、`settings.section` / `settings.plugin.item`（配置面板）。
证据：Cordis Inspect → client / Slots / `listSubTree`。

### F7 已有「边流边观察模型输出」的成熟先例
host 侧 tap `llm/stream`（waterfall，纯观察、不吞 chunk、不修改），再经 SSE 推给浏览器。
证据：`D:\developing\DSH-plugin\dsh-hmm-wait\src\index.ts`。

### F8 本机插件工程形态已经固定
TS 源码 → `tsdown` 打成 `lib/index.js`（host）与 `lib/client.js`（client）；`package.json` 的 `dsh.bundle.patch` 指向自带的 `cordis.patch.yml`（insert 一行）；用 `dsh plugin --profile web add link:D:\developing\DSH-plugin\dsh-memes-reply` 装进 web profile。
证据：`~/.dsh/profiles/web/package.json`（`dsh.profile.bundles` + `link:` 依赖）与 `~/.dsh/profiles/web/cordis.patch.yml`。

## 3. 需求草案（8 个待定决策）

| # | 决策 | 选项 | 我的建议 | 影响面 |
| --- | --- | --- | --- | --- |
| D1 | 呈现形态 | (a) 回复正文内联图片 (b) 气泡旁浮动贴纸层 (c) 工具卡贴纸 | **a 先做，b 二期** | a 零 UI 改动；b 要写整个 client 半边 |
| D2 | 谁决定贴哪张 | (a) 模型自己写 (b) 模型调工具选 (c) 规则自动匹配 (d) 用户显式 `/fish` | **b + d 起步**，a/c 备选 | 直接决定 token 成本与准确度 |
| D3 | 触发时机与频率 | 每条回复一张／仅合适时／N 轮冷却／仅点名时 | **默认「仅合适时」**，硬上限每轮 ≤1、3 轮内不重复 | 决定"可爱"还是"烦人" |
| D4 | 资产工程化 | (a) 直接引用原目录 (b) 压缩副本进插件包 (c) 压缩副本进 `~/.dsh` (d) 进附件库 | **c + 一次性导入脚本**；a 作退路；d 只在接受丢动画时用 | 460 MB → 预计 30–60 MB |
| D5 | 语义索引 | 文件名切词＋人工校对／向量检索 | **关键词即可，不需要向量库**；产 `index.json` | 157 条用向量是杀鸡用牛刀 |
| D6 | 性能与缓存 | 原图直出／压缩副本 | **压缩副本 + `immutable` 缓存 + ETag**，禁走 `/api/file` | 均值 3 MB／张，不处理会明显卡 |
| D7 | 作用域与分发 | 仅 web profile／仅某 preset／对外发包 | **先只在 web profile 挂一行**，配置里给开关 | 影响资产放哪、要不要进包 |
| D8 | 开关与降级 | 总开关／每会话静音／缺失降级／CLI 不注入 | **全部要** | 没有降级就会出现"破图 + 长 URL" |

### 补充说明

**D5 索引形态**：`index.json` 每条至少含
`{ id, file, name(中文), tags[], mood, bytes, sha256, w, h }`。
`id` 用 ASCII 短名（如 `dianzan`、`aixin-1`）便于写 URL 和心智记忆；带序号的文件（`爱心 1/2/3`）要处理重名。英文／缩写条目（`Bug`、`Popcat`、`Raid`、`Bits`、`UU`）文件名提供不了中文语义，需要人工补标签。

**D6 为什么必须压**：`/api/file` 是 `no-store` 且无 Range；即使走自有路由，3 MB 的 GIF × 一屏两三张 = 十几 MB 流量。目标是单张 ≤400 KB（缩到 240–320px 边长 + gifsicle 有损压缩），配合 `Cache-Control: private, max-age=31536000, immutable` + sha256 ETag，**同一张只下载一次**。

**D8 降级**：素材 404 / 未导入时，正文里必须**什么都不显示**（而不是出现 `![](http://...)` 这样的长 URL 或破图）——这要求"清单里的 id ↔ 路由里真实存在的文件"由同一份 index.json 派生。

## 4. 四条实现路径对比

### 路径 A：正文内联 markdown + 自有资源路由 ★ 推荐 MVP

**做法**：host 半边 `ctx.webServer.register({kind:'prefix', path:'/api/dsh-memes-reply'})`，提供
`GET /api/dsh-memes-reply/sticker/<id>.gif`（流式读文件、正确 Content-Type、immutable 缓存、404 干净降级）；
再给模型一份「素材清单 + 写法约定」（一条 skill 或一个工具）。
模型在回复里写：`![](http://127.0.0.1:3080/api/dsh-memes-reply/sticker/dianzan.gif)`

- ✅ 不动 DSH 任何既有 UI；✅ **保留 GIF 动画**；✅ **流式期间就出图**（F2 分支 1）；✅ 不碰附件库；✅ 实现量最小（host 一个文件 + 一份索引）。
- ⚠️ URL 里硬编码 origin/port（可在运行时把真实 origin 注入提示词）；⚠️ 正文 markdown 源码／CLI／会话导出里会看到 URL 原文；⚠️ 样式完全由既有 CSS 决定（不能自定义圆角/描边/点击放大）；⚠️ 做不了冷却、去重、悬停动效这些交互。
- 风险：origin 不一致（LAN IP、Electron、换端口）。缓解：host 从浏览器请求的 `Host` 头学习真实 origin，或读 `ctx.webServer.port` 后写进提示词。
- 工作量：**2–4 小时**。

### 路径 B：路径 A + 客户端贴纸层（最终形态）

**做法**：保留 A 的路由，另加 client 半边：注入 `shell.overlay`（浮动贴纸，像 `dsh-pet`）或 `conversation.chat.turnTail`（跟着这条回复走）；host 通过 SSE 告诉 client「这轮贴哪张」。

- ✅ 完全可控：尺寸／圆角／描边／点击放大／悬停微动；✅ 可做冷却、去重、设置面板；✅ 可做「打字中/思考中」彩蛋（F7）；✅ **不污染正文文本**。
- ⚠️ 多一整个 client 半边（React + 槽位 + 设置面板），构建链更长、调试贵一个数量级；⚠️ 浮层要和现有 `鲸鱼娘` pet 抢视觉；⚠️ 贴纸与"哪条消息"的绑定要自己维护（滚动、历史重放、刷新）。
- 工作量：**1–2 天**。

### 路径 C：工具卡贴纸

**做法**：注册模型工具 `use_sticker(emotion)`，工具卡通过 `tool.call.toolview` 自己渲染贴纸。

- ✅ 语义明确（"用了一次贴纸"是显式事件）；✅ 卡片有独立空间，可带灯箱。
- ⚠️ 打断阅读流；⚠️ 若想复用官方图片组（`tool.call.images`）就必须把图片交给附件流水线 → **丢动画（F5）**；⚠️ 自己渲染＝又写一条客户端渲染路径。
- 工作量：客户端 1 天 + host 半天。

### 路径 D：零代码基线（只用来自测，不作为产品）

**做法**：不写插件，直接让模型写 `![](/D:/Pictures/image_ACG/蓝色大肥鱼表情包/xxx.gif)`（命中 F2 分支 2 → `/api/file`）。

- ✅ 今天就能试，0 代码。
- ⚠️ 只对**绝对 POSIX 风格路径**生效；Windows 盘符形式 `/D:/...` 能否过 `fs.resolve()` **未验证**；⚠️ `/api/file` 有鉴权（见 F3 的 ⚠️）；⚠️ `no-store` + 无 Range + 均值 3 MB → 每次渲染重下，多图明显卡；⚠️ 流式期间不出图。
- 用途：**5 分钟可行性探针**很好，作为产品不合适。

## 5. MVP 验收标准

1. 装上后，在 Web GUI 的一轮对话里，模型能在回复中发出一张**会动**的大肥鱼，且**流式过程中就能看到**；
2. 157 张素材有稳定的 ASCII `id` ↔ 中文名映射；文件缺失时正文里**不出现**破图与长 URL；
3. 图片响应带 `immutable` 缓存与 ETag，刷新页面不重复下载同一张；
4. 设置面板有总开关，关掉后新回复都不再带图（历史里的图仍能显示）；
5. 不改变任何既有 UI 布局；卸载后工作区无残留。
