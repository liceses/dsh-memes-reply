## 1. 为什么是"先判族、再选张"

这是本轮最重要的一个决定，**量出来的，不是猜的**。三次真实 API 调用（2026-09-20，
`state` 同一份：`assistant_reply = "验收完成，全绿。踩了个坑：Windows 沙箱下 curl.exe 的 TLS 必然报
SEC_E_NO_CREDENTIALS，换成 node 的 fetch 就好了。"`，`recently_used = [qingzhu, gongzuo-shengqi]`）：

| 问法 | 延迟 | 成本/轮 | 选中项 | margin |
| --- | --- | --- | --- | --- |
| **只问 13 族**，族内由代码挑（**采用**） | **1.3 s** | **$0.00005** | `celebrate 0.61`（次选 `bug 0.31`） | 0.30 |
| 族 → 具体张（两次调用） | 3.5 s | $0.0001 | 族 `celebrate 0.61` / 张 `qingzhu 0.81` | **0.72** |
| 157 张直选（一次调用） | 1.0 s | $0.00022 | `all-good-1 0.29`（次选 `qingzhu 0.27`） | **0.02** |

结论：

1. **157 路直选会糊**（margin 0.02，概率摊在 14 个 label 上）。JEV 对**窄候选集**明显更可靠。
2. **一次调用判族 + 代码选张**是最优解：延迟与成本都是最低档，而语义判断发生在 JEV 最稳的那一层。
3. "族里到底选哪张"（三张几乎一样的「一切都会好」）本来就该由代码定 —— 顺带把**冷却去重**与
   **确定性**一起解决了，这两件事让模型做只会更差。

这与 JEV 自己的纪律一致：**精确规则与算术用代码，Jev 只做判断**（`skills/jev/SKILL.md` §Decision loop）。

### 1.1 族是怎么划的

`src/moods.ts`：13 族 + `blank`，共覆盖 157 张里的 152 张（人工整理）。

```
celebrate 庆祝·成事 / praise 点赞·打气 / bug 翻车·自嘲 / sad 委屈·害怕 / thinking 思考·认真
confused 困惑·呆住 / tired 摸鱼·想睡 / angry 不满·叫停 / shy 害羞·卖萌 / greet 打招呼·收尾
notice 提醒·交代 / gift 送礼·表白 / expect 期待·稍等 / blank 无情绪
```

- 族 key 是 ASCII 且稳定（它就是协议），gloss 是给 JEV 看的中文语义说明。
- 未收录的 5 张仍在，只是不作为 JEV 候选：`keyword` / 模型点名 / `latch` 照样能选到它们。
- `test/jev.test.mjs` 有一条回归盯着"**族表里的 id 必须真实存在**，且没有一个 id 进两族" ——
  人工表没有门禁就会悄悄失效。

## 3. 方案

### 3.1 分工（相对 v2.0 的唯一变化）

```
v2.0：  宿主（字节 + 数据）  ←  客户端（纯函数派生：latch > 模型点名 > keyword/every > 兜底）
v2.1：  宿主（字节 + 数据 + **JEV 决策**）  ←  客户端（异步取一次 /jev-pick，再走同一套派生）
```

派生优先级增加一档，位置是刻意的：

```
latch（人手动点的） > jev（这轮语境算出来的） > 模型点名（id/mood） > keyword/every 规则 > 兜底
```

**"人 > 语境 > 模型 > 规则 > 兜底"** —— 人按的那一下永远最大。

### 3.2 为什么决策必须在宿主，且必须绕过纯函数

- **key 的位置**：`src/client/*` 会被 `scripts/check-client-purity.mjs` 挡在门外，API key 进不去也不该进去。
- **纯函数的位置**：`finalStickerFor()` 是 `useMemo` 里的同步纯函数（v2.0 §3.3 的简化），
  而 JEV 调用是异步 + 非确定的 —— 硬塞进去就等于把"刷新即重放"砸掉。
  所以客户端**只取结论**（`/jev-pick`），拿到 id 后仍旧走那条原有的纯派生。
- `src/auto.ts` 里 `mode === 'jev'` **显式返回 `null`**：这个纯函数没有能力知道结论，
  若在这里退回 `every` 规则，就会先闪一张随机的再被换掉。

### 3.3 缓存（N1 的唯一实现）

结论缓存在**路由实例的闭包**里（`createDecisionCache(256)`，FIFO + 重设即置新）：

- 活得比一次请求长 → 刷新能重放；
- 随 `ctx.effect` 一起消失 → 不留跨生命的脏状态；
- **失败也缓存** → 一个轮次最多一次尝试，网络抖动不会变成每帧重试的循环。

### 3.4 绝不拖住会话（N2）

| 失败面 | 处理 |
| --- | --- |
| 没 key | 直接不发请求，`no key` |
| HTTP 非 2xx（401/402/429/5xx） | `http <status>` |
| 响应畸形 / 未知 label / 概率越界 | `bad response`（JEV 文档要求：**畸形响应是错误，不是放行**） |
| 超时 | `AbortController` **+ `Promise.race`** 双保险 |

最后一条值得单说：只挂 `AbortController` 是不够的 —— 万一某个 `fetch` 实现不看 `signal`，
`await` 会永远挂着，而"绝不拖住会话"正是这个功能的命根子。（写这条时先只用了 signal，后来补的竞速。）

### 3.5 读 key（N3）

顺序：`OPENROUTER_API_KEY` → **`<DSH_HOME>/.credentials.yaml` 兜底**。

为什么需要兜底：本机实测 DSH 把 key 存在那个文件里，而**没有注入插件进程的环境变量**
（`process.env.OPENROUTER_API_KEY` 是空的）。只做正则取值、不解析 YAML —— 不为了一个 key
把 yaml 依赖拖进插件。key 永不打印、永不写日志，只进 `Authorization` 头。

### 3.6 调试通道为什么单独一条端点（F7 / N5 / N6）

宿主在内存里留一个环形日志（最近 20 趟**真实往返**），经 `GET /jev-log` 给面板。

| 决定 | 理由 |
| --- | --- |
| 与 `/stats` **分开** | `/stats` 是 12 秒轮询的常客，一份往返带请求/响应原文（裁剪后各 1–4 KB），挂进去等于每轮都搬一堆没人看的 JSON。`/stats` 只留计数 |
| **只记真实往返** | 一次刷新会重放好几个回合。缓存命中若也记，真正发生过的调用会被淹掉；"缓存了多少次"由计数表达 |
| **失败也记，且带 HTTP 状态 + 响应正文** | 402 欠费 / 429 限流那一类的正文是排障唯一线索；"发了但失败"与"根本没发（无 key）"必须能分开 —— 后者 `request` 是 `null` |
| 请求/响应**裁剪 + 显式标注** | 回复正文最长 12k 字符（`capped()`，1.2k 截断 + "原文 N 字符"）。不封顶的话决策缓存 256 条会变成几 MB 常驻内存 |
| 客户端的开关是**配置项**（`jevDebugVisible`），位置写在 `state.json` 的 `jevDebug` 槽 | 复用挂件那套（`shell.overlay` + `/layout`）。`slot` 缺省仍按 `pet` 解释，**老客户端不带这个字段也不会坏** |
| 面板**只在展开时**轮询（2.5 s） | 收起来就不该继续吵宿主 |
| 面板**没有任何写操作** | N5：不重发、不改族表。排障工具不该能改变被观测的东西 |

## 6. 风险与局限（诚实清单）

1. **隐私**：开 `jev` = 助手每轮回复正文发到 OpenRouter（截断 12k 字符）。默认关着。
2. **成本**：$0.0000488/轮（约 1 万分之 5 美分）。已在 `/stats` 的 `jev.costUsd` 记账。
3. **延迟**：多等约 1 s 才出图（直连 784 ms / 代理 2268 ms）。这期间刻意什么都不显示。
4. **非确定**：同轮次靠缓存钉住；跨轮次本来就会变（这是特性）。
5. **外部依赖**：没 key / 欠费 / 断网 → 静默回落既有规则。`/stats` 与轨迹能看出来，但**用户不会被打断**。
6. **`needs_review` 是常态**：默认阈值 0.8/0.15 只是示意值，**不能**把它当"不确定就当失败"用。
7. **族边界有主观性**：`庆祝` 与 `翻车自嘲` 在"验收全绿但踩了坑"这类回复上真的两可（实测 0.61 vs 0.31）。
   这不是模型不准，是这条回复本来就有两副面孔。
8. **JEV 会错、会过自信、可被正文内容影响**：它给的是判断，不是授权。这里只用来选一张表情包，
   所以后果有界 —— 这正是它适合的位置。
9. **调试浮层是给人眼的，不是取证工具**：条数封顶 20、单条长文本截断 1.2k 字符、只存内存。
   要看全文得自己拿 key 打端点。
