## 2. 需求

### 2.1 功能需求

| ID | 需求 | 验收方式 |
| --- | --- | --- |
| FR1 | `GET /api/dsh-memes-reply/sticker/<id>.gif` 经插件自有路由返回 **动画 GIF 原字节**（GET/HEAD、`Content-Type: image/gif`、`Content-Length`、`ETag`(sha256)、`Cache-Control: private, max-age=31536000, immutable`）；未知 id → 404 JSON，绝不返回 HTML | 裸 HTTP：200 + `GIF89a` 魔数；未知 id：404 |
| FR2 | `assets/index.json` 是唯一事实源：`{id, name, tags[], mood, file, bytes, sha256, w, h}`；157 条；带序号的重名（爱心 1/2/3）生成稳定 ASCII id；**文件不存在的条目不写入索引** | 索引条数 = 实际可服务文件数 |
| FR3 | 模型工具 `use_sticker(mood, id?)`：按关键词/情绪返回贴纸；**每轮最多 1 张**，第二次调用返回"本轮已用过"的失败结果并附提示；`form=inline` 时返回可直接粘贴的 markdown 片段，`form=sticker` 时只登记本轮贴纸、不返回 URL | 连续调用两次：第二次失败 |
| FR4 | 斜杠命令 `/fish`：`/fish`（列 id + 当前状态）、`/fish <id\|关键词>`（下一轮指定贴纸，一次性）、`/fish off\|on`（本会话静音） | 命令行执行后状态变化可见 |
| FR5 | 设置面板（命名空间 `dsh-memes-reply`）：总开关、`form`（inline/sticker）、`quality`（compressed/original）、`assetRoot`、`originalRoot`、`cooldownTurns` | 设置项即时生效 |
| FR6 | 本会话静音与总开关都生效时，**新回复不再带图**；历史里的图仍可显示 | 关掉后连续两轮无图 |
| FR7 | 诊断端点 `GET /api/dsh-memes-reply/stats`：贴出次数、命中/未命中、当前 mode、素材根 | 返回 JSON |

### 2.2 非功能需求

| ID | 需求 | 理由 |
| --- | --- | --- |
| NFR1 | 默认走**压缩副本**（缩到 240–320px、单张 ≤400 KB）；`immutable` + `ETag` 保证同一张只下载一次 | 原图均值 3 MB，直出会拖垮界面 |
| NFR2 | 素材缺失/404 时**正文无痕**：inline 模式下工具先校验文件存在再返回片段；不给模型返回可能 404 的 URL | 避免"破图 + 长 URL" |
| NFR3 | 读盘一律走 `ctx.fs`（受 FS 沙箱策略约束），不绕过策略；路由仅接受**回环 Host**，不发任何 CORS 头 | 与 `dsh-showme-html` 同款围栏 |
| NFR4 | 路由/工具/命令/设置全部由 `ctx.effect` 或注册器返回值持有，停用即净 | 卸载后无残留 |
| NFR5 | 上下文成本要记账：`inline` 每条 URL ≈ 30–40 token 进正文历史；`sticker` 形态正文里只有一句话（0 URL） | 长会话里的真实成本差异 |

## 3. 方案与模块划分

```
dsh-memes-reply/
├─ package.json            # dsh.bundle.patch → cordis.patch.yml；dsh.client → lib/client.js
├─ cordis.patch.yml        # insert 一行（id: memes-reply, name: dsh-memes-reply）
├─ src/
│  ├─ index.ts             # host 半区入口：挂路由 + 工具 + 命令 + 设置
│  ├─ assets.ts            # 索引加载 / 双根解析（compressed → original）/ id 规范化
│  ├─ route.ts             # /api/dsh-memes-reply/sticker/<id>.gif 与 /stats（回环围栏、ETag）
│  ├─ tool.ts              # use_sticker：关键词检索 + 每轮限额 + 形态分支
│  ├─ command.ts           # /fish
│  ├─ schema.ts            # 设置 schema（含默认值）
│  └─ client/index.tsx     # 【M2】贴纸渲染（形态 B）
├─ assets/                 # 压缩副本 + index.json（随包分发）
├─ scripts/import-assets.mjs  # 从任意目录导入：切词 → 压缩 → 生成 index.json
└─ docs/
```

### 形态 A（inline）数据流
```
模型 → use_sticker(mood) → host 查索引 → 命中且文件存在
     → 返回 ![](http://<origin>/api/dsh-memes-reply/sticker/<id>.gif)
模型把该片段写进回复 → 浏览器 markdown 渲染 <img>（流式期间就出图）
```
- origin 由 host 在运行时注入（`ctx.webServer.port` + 浏览器 `Host` 头学习），不硬编码。

### 形态 B（sticker）数据流
```
模型 → use_sticker(mood) → host 登记「本 turn 的贴纸」
     → client 半区在该 turn 的位置渲染贴纸（可控尺寸/点击放大/悬停）
```
- 候选实现两条，**推荐 B-1**：
  - **B-1（推荐）**：`tool.call.toolview`（按工具名 key 注册）——贴纸落在该工具调用在会话流里的位置，用负边距/绝对定位做成"气泡旁的浮动贴纸"观感。**不需要读会话状态、不需要 SSE**，风险最低。
  - **B-2（进阶彩蛋）**：`shell.overlay` + host 经 SSE 推送（复用 `dsh-hmm-wait` 的现成模式），可做「打字中/思考中」指示器（素材里有 `打字(普通/生气/恼怒)`、`思考(认真地/自信地)`）。代价：要和现有 `鲸鱼娘` pet 抢视觉，还要自己维护"贴纸 ↔ 哪条消息"的绑定。

### 8.3 M1 期间的决策更新

- **素材格式改为动画 WebP（保留全部帧）**：GIF 在"保 320px + 可接受体积"下必须把帧率砍到 10–20fps。
  实测同一张图：全帧 WebP 320px/q40 = 630 KB，而砍到 12fps 的 GIF = 264 KB。
  最终落地：**157 张 / 85.9 MB / 均值 560 KB / 最大 1195 KB**（73 张保住 320px）。
  体积旋钮已就位：`--fps 25` 约 45 MB（同图 333 KB），`--fps 20 + --max-bytes` 还能再压。
- **新增 `--reindex`**：只重算派生元数据（尺寸/帧数/时长/字节/sha256），不重新编码——
  换格式或修 probe 逻辑后不必再压十几分钟。
- **probe 必须带 `-count_frames`**：动画 WebP 只在 `nb_read_frames` 里有帧数，且 `format.duration` 为空，
  时长要用 帧数/帧率 反推。（这条是 `test/index.test.mjs` 抓出来的真 bug。）
- **压缩策略改为"保尺寸优先"**：320px 是前端 markdown 图片的满尺寸显示上限
  （`width:auto; max-width:100%`），所以阶梯先保 320px，再让质量/帧率退让。
- **每轮限额用两个 host 事件驱动**：`agent/pre-step` 记当前 turn、`agent/turn-stopping` 关轮；
  观测不到 turn 的流程（子代理等）退化成 60 秒窗口兜底。

### 8.5 活体测试抓到的第 2 个真 bug

第一次真调用 `use_sticker("得意")` 返回 **"没有匹配"**——而 `得意` 正是**我写在工具描述里举给模型看的例子**。
根因：`sticker-map.json` 的标签是按"语义名"编的，没有覆盖"人/模型实际会说的情绪词"。
修法（两处，防复发）：

1. 补标签：得意/得瑟、感谢/谢谢、无聊/发愣、划水、崩溃/破防、气死、厉害/牛、着急/焦虑（14 条索引随之更新）；
2. `--reindex` 现在会**重新套用 `sticker-map.json` 的标签**（原先只重算元数据），改标签 30 秒生效，不必重压；
3. 新增回归测试 **「工具描述里的示例词都能命中」**：从 `description` 里正则抽出"例如：…"那段，
   逐个断言检索得到——以后往描述里加例子却不打标签，测试会直接红。

## 9. M1.7 配置面板（原生风格）

### 9.1 起因（查证结论，不是猜测）

- `settings.plugin.item` 的占用者只有 `dsh-hmm-wait`、`auto-proxy`、`shell`、`agent-loop`、
  `subagent-model-selection`、`web-search-deepseek`；**没有 `dsh-memes-reply`**。
- 原版 `ConfigurablePluginsTab` 的规则是：卡片 = **Host 提供的 settings 命名空间 ∩ 注册进该槽位的卡片**，
  源码注释原文 *"A served namespace no card claims renders nothing"*。
- 原版 bundle 里搜不到 `hmm-wait` / `auto-proxy` 字样 → 卡片必须由插件自己注册，不存在"自动生成"。
- ⇒ 我们只注册了 host 侧命名空间，没有浏览器半边，所以设置里**什么都不显示**。

### 9.2 交付

| 面 | 内容 |
| --- | --- |
| host 端点 | 新增 `GET /thumb/<id>.<ext>`、`GET /catalog`、`GET/POST /latch`；`/stats` 增补 `totalBytes`/`latch` |
| 素材管线 | `--thumbs`：首帧 160px 静态 WebP（157 张共 1.0 MB，均值 7 KB）；索引新增 `thumb` 字段 |
| 状态 | `state.json` 增 `global.latch`（面板的"下一轮用这张"）；工具取图优先级 会话指定 > 全局指定 > id > 检索，命中即双清 |
| 浏览器半边 | `src/client/`：折叠卡片（状态行 / 6 字段＋逐字段「默认」/ 12 格预览墙 / 换一批·取消指定·丢弃·保存），全用 `--dsw-alias-*` |
| 设置通道 | 官方 `ctx.settingsScope.bind({namespace})` 的 `getSnapshot/subscribe/set/unset`（**不用自定义 RPC**） |
| 构建 | `src/client/**` 由 tsdown 打成 `lib/client.js`（CJS closure + 平台模块 external）；host 仍由 tsc 直出 |
| 门禁 | `scripts/check-client-purity.mjs`：bundle 里出现 schemastery / `node:*` / 白名单外 require 即失败 |

### 9.3 决策记录

- **面板放 `settings.plugin.item`（key = 命名空间）**，与原版惯例和 `dsh-hmm-wait` 一致；
  独立设置页（`settings.section`）留作备选（用户选择前者）。
- **预览墙要**（用户确认）：为此加了缩略图管线；预览墙只加载静态缩略图（12 张 ≈ 84 KB），
  点击后才加载 1 张全尺寸动画确认——否则 12 × 560 KB 会把面板变成流量黑洞。
- **把"下一轮用这张"放全局而非按会话**：设置面板是 root scope，拿不到当前 sessionId；
  语义上"下一次工具调用用这张"也正好是用户按下按钮时的心智模型。
- **客户端样式用官方主题变量手写**（本部署的客户端服务目录里没有 `styles` 服务），
  卡片形态照抄官方折叠卡片与 `dsh-hmm-wait` 的既有观感。

### 9.4 测试

`npm test` 共 **30 个测试**（原 19 + 新增 11）：路由新增缩略图/清单/latch 分支（含 limit 夹取、
seed 可复现、非法输入、非 JSON、错误方法）、装配新增"面板指定被下一次工具调用消费并清空"与
"会话指定优先于面板指定"、真实缩略图体检（静态、≤160px、均值 ≤20 KB）、客户端 bundle 契约与纯净化门禁。

### 9.5 重启后的活体验收（已完成）

## 10. M1.8 「别的会话为什么不贴纸」：查证与解法（A+B）

### 10.1 用户问题与查证过程

用户问："为啥其他的会话没见过贴纸啊"。查证里踩了一个坑：DSH 会话日志（`session.v3.jsonl.zstd`）
是**每个事件各自成一个 zstd 帧**的，单帧解压（`zstdDecompressSync` / 流式）只能读到开头——
第一版统计因此得出"0 个会话用过"的错误结论。改成"按 zstd 魔数切帧、逐帧解压后拼接"后，
先用**本会话当阳性对照**校准（本会话应出现 16 次工具被提供 / 9 次调用 / 211 个贴纸 URL，实测吻合），
统计才可信。

### 10.2 结论（数据）

| 会话（按最后活动） | 工具被提供 | 真实调用 | 贴纸 URL |
| --- | --- | --- | --- |
| 本会话 | 16 | 9 | 211 |
| `中医研究` | 2 | 0 | 0 |
| `ds-tts` | 6 | 0 | 0 |
| `showmeWithHTML` | 1 | 0 | 0 |
| `deepseekharness` | 1 | 0 | 0 |
| 装好之前（9/14 23:21 及更早，8 个） | 0 | 0 | 0 |

- 工具**对所有会话都可用**（装好后跑过的会话，每次请求的工具目录里都列着 `use_sticker`）；
- 但除了本会话，**没有任何会话调用过它**（0 次调用、0 个贴纸 URL）；
- 装好之前的会话压根没有这个工具。

根因：**可用 ≠ 会用**。它排在 71 个工具目录的末尾，描述又被刻意写成克制版；在正常写代码/查问题的
上下文里，模型没有理由去动一个装饰性工具。本会话有，是因为上下文一直在讨论这个插件。

### 10.3 解法（用户选 A+B）

| 旋钮 | 实现 |
| --- | --- |
| **A. 系统提示加一行** | `src/prompt.ts`：用官方的 `ctx.systemPrompt.section()`（由 dsh-system-prompt 提供）注册 `dsh-memes-reply:hint`，顺序锚在 `TOOLS_SDK` 之前（= 所有内置工具说明之后）。`text` 是函数，**只在工具真的注册了 + 总开关开着 + 本会话没被 `/fish off` 静音**时输出提示，否则输出空串（0 token）。约 60 token/请求。 |
| **B. 放松工具描述** | `src/tool.ts` 的 DESCRIPTION：从"仅在确实贴切时使用"改成"合适的收尾可以贴一张：问题被修好、踩了坑、想夸一句、报告成功或失败、长任务收工"（`例如：…。` 那段保留，回归测试靠它抽示例词）。 |

关键 API 事实（都是查过的，不是猜的）：
- `AssembleContext` 的基底类型只有 `{scope?, signal?}`，但 `dsh-agent-loop` 用
  `context.agent?.session.header.cwd` —— 即上下文里有 `agent`（由 dsh-agent 声明合并进来）。
  我们只按结构读 `context.agent?.id` 拿会话 id，**不为类型拉 dsh-agent 依赖**；
- 顺序表 `SECTION_ORDERS` 里工具段是 1000–2900（TOOL_BASH…TOOL_REPORT），`TOOLS_SDK: 5000`；
  取 `getSectionOrder('TOOLS_SDK') - 100`，取不到就退 4900；
- waterfall 版的 `system-prompt/assemble` 也能改装配结果，但文档明确"registered complete section
  is restored after this waterfall"（有些 scope 会把自己的完整提示还原），所以走 provider 正路更稳。

### 10.4 新增测试

`test/apply.test.mjs` 加一个用例：断言段名/顺序落在内置工具段之后；默认输出提示；没有 agent 的根装配
也输出；`/fish off` 后该会话不输出而别的会话照常；总开关关掉后全局不输出。
`npm test` 现为 **31 个测试**。

## 11. M1.9 「扒源码收工」事故：三个叠加的 bug 与修法

### 11.1 现场（日志取证）

用户报：「ai 会调用 `"mood": "扒源码收工"` 这样的 mood，导致没有贴纸」。日志核对（make-videos 会话 18:09）：

同会话的装配后系统提示里，确实带着 M1.8 新加的我们那一行（含「**任务收工**」这个例子）。

### 11.2 三个叠加的 bug

| # | Bug | 责任方 | 证据 |
| --- | --- | --- | --- |
| 1 | **展示给模型的词，检索不到**：提示里写「任务收工」，而 `sticker-map.json` 里根本没有「收工」这个标签 | **我**（提示文案与词表脱节） | 模型把「任务收工」echo 成了「扒源码收工」 |
| 2 | **中文检索太死板**：`扒源码收工` 被当成一个 5 字整串，没有子串/助词/二字回退 | `search.ts` | `tokenize` 只做分隔符切分 |
| 3 | **失败后没有恢复路径**：只回了"换一个更具体的情绪词"，**没说可以重试**，也没给能命中的词 | `tool.ts` | 模型直接「跳过」，这一轮就再也没鱼 |

第 1 条是第 2 次同类事故（第一次是「得意」）——所以这次把它升级成**纪律**而不是补丁。

### 11.3 修法

| 层 | 改动 |
| --- | --- |
| **检索容忍度**（bug 2） | `tokenize` 对每个中文片段生成三个"切分基"：剥尾助词（修好了→修好）、去所有助词（踩了坑→踩坑）、原片段（≥3 字）；每个基再补相邻二字组合与首/尾二字。**≤2 字的短查询行为完全不变**（`点赞`/`哭` 这类精确查询不能被弄糊）。 |
| **词表补桥**（bug 1） | `sticker-map.json` 补：收工/完工 → 庆祝 与 停止工作；修好/修复/踩坑/调通 → Bug；夸/夸奖 → 点赞；跑通/通过 → 一切都好。`--reindex` 30 秒生效。 |
| **展示词纪律** | 新增回归测试：**从 `HINT_TEXT` 的「（…）」里正则抽出场景短语**逐个断言可命中——和之前「工具描述示例词」那条一个思路。凡是给模型看的词，都必须被自己的检索器命中。 |
| **可执行的失败**（bug 3） | 失败文案改成：「没有匹配「X」。请用 mood 传一个 2–4 字短词**立刻重试**（本轮还没用过贴纸，可以重试）：收工、完成、开心、翻车、点赞；或直接传 id」。并复用 `RETRY_WORDS`（也有回归测试盯着）。 |
| **接口收紧** | 工具描述与 `mood` 参数说明都写明「**必须传 2–4 个字短词，不要传整句**」；`required` 从 `['mood']` 放开（给 `id` 时可以不给 mood）。 |
| **兜底开关**（可选保险） | 新设置 `fallback`（兜底贴纸 id，默认空=不兜底）。开了之后一个词都不匹配时用兜底贴纸，并在工具结果里**如实说明"用了兜底"**。默认关：这样检索问题不会被悄悄掩盖。面板里也加了这一项（现在 7 个字段）。 |

### 11.4 修复后的检索实测

## 14. 第二层：气泡角上的圆贴纸（复刻效果图）

### 14.1 座位与让位

`conversation.chat.turnTail`（**chain**）+ **`priority: 10`**。链式条目按 priority 升序尝试、第一个非空者独占渲染，
所以排在 `present` 交付卡片（0）之后：**有交付卡片的回合不显示贴纸，交付卡片完全正常**。
代价明确、可接受（那一回合挂件还在，所以"随时能看到"不破）。

### 14.2 三件套：为什么不能只写一个组件

链的 `select` 是**同步纯函数**，ownerProps 只有 `{turn, seq, openFile}` —— 没有 `sessionId`、也不能异步。
所以拆成三件：

| 件 | 文件 | 职责 |
| --- | --- | --- |
| 隐形轮询器 | `src/client/poller.tsx` | 坐 `conversation.input.dock`（常驻 + 拿得到 `sessionId`），只把 `/auto/pending` 的事件搬进仓，渲染 `null` |
| 落地仓 | `src/store.ts` | `Map<turn, {event, at}>` + 收起标记；`peek(turn)` 是**纯查询**（反复调用不会消费掉 —— 否则链每次重渲染贴纸就闪没了） |
| 链式座位 | `src/client/bubble.tsx` | `select: owner => store.peek(owner.turn.turn)`；组件内再用 `matched.sessionId === props.sessionId` 核对一次 |

`owner.turn` 是 `TurnLocation`（`{turn: number, start, end, status, steps, data}`），轮次号在 **`turn.turn`** 上 ——
与 host 事件里的 `turn` 是同一个东西。这一条是查了 `conversation.d.ts` 才确认的（第一版写成 `owner.turn` 直接编译不过）。

### 14.3 提前发布（解决"事件晚于渲染"）

第一版在 `agent/turn-stopping` 才决策，晚于客户端看到 `turn/end`，有"事件没赶上渲染"的风险。改成：

- `tapTextStream` 额外检测**这一路流有没有产生工具调用**（认 `tool-call` / `tool-call-delta` /
  `block-start.blockType==='tool-call'` / `block-end.block.type==='tool-call'`）；

## 15. 事故复盘：为什么"每条回复右下角都有鱼"整整七轮都没出现

### 15.1 表面症状

用户反复重启，`bubble-mount` 计数**始终为 0**，右下角什么都没有。而 host 日志显示自动贴纸
**一直在正常发布**（`recent` 里有 `qian`/`hongbao-1`/`zheshan`…）。

### 15.2 四个真问题（层层掩盖）

| # | 问题 | 证据 | 修法 |
| --- | --- | --- | --- |
| 1 | **渲染期竞争**：等"流结束"才发布，而链的 `select` 在渲染那一刻同步判定，轮询 800ms 才拉一次 → 约 94% 必 miss | `client:select turn=20 miss` 之后不再重渲染 | `every` 模式改到 `agent/pre-step`（轮次开始）发布 |
| 2 | **游标跨进程失效**：`dsh web` 重启后 host 的 `seq` 归零，浏览器里的旧游标还停在上一进程 → `event.seq <= since` **永久**过滤 | 需要重启才复现 | `pending` 把"超前"的游标夹回 0 |
| 3 | **两侧轮次号不同且漂移**：host 用 agent 计数器、客户端用会话事件计数器，实测 23 vs 20 | `host:publish turn=23` 对 `client:select turn=20` | 绑定改看 **`ownerProps.seq` 水线**（单调递增，与编号体系无关） |
| 4 | **`turnTail` 是竞争链，我把自己排在交付卡片之后**：回复里提到文件路径就生成交付卡片 → 链在 priority 0 被接走 → **我的 selector 一次都没被调用** | `client:select` 只被问过早期几轮；`client:fallback-shown` 的 note 直接写着"交付卡片占了尾巴座位" | 用户拍板保留让位；补 `shell.overlay` 兜底通道（2.5 秒无人认领即显示同一形态的圆贴纸） |

### 15.3 教训

1. **先建可观测性，再改逻辑**。前三个修的都是真 bug，但每一个都被第四个掩盖着 ——
   没有 `trace`（host 决策 + 客户端回执的双向环形缓冲）就只能一直猜。
   浏览器控制台看不到的地方，必须让客户端把关键动作**回传到我能读的接口**。
2. **"优雅降级"要先测量它的触发频率**。我评估"有交付卡片的回合很少"，而用户正好在这个
   **每条回复都提文件路径**的会话里验收 —— 失败率被我调成了 100%。
3. **不要在两个子系统各自计数的字段上做对齐**（轮次号）。选一个单调、跨边界稳定的锚
   （这里是会话日志的 `seq`）。
4. **让位设计要留观察点**：如果当初 `fallback` 的 note 不写原因，第四次事故还得再挖一轮。

### 15.4 第五个问题：贴纸出现得太早，用户读到回复时它已经没了

```
22:08:13  host:publish          turn=25  id=dai-tiezhi-2     ← 轮次一开始（我还在写回复）
22:08:16  client:fallback-shown turn=25  id=dai-tiezhi-2     ← 2.5 秒后就冒出来了
22:10:36  host:turn-stopping    turn=25                       ← 而这条回复 2 分 23 秒后才写完
```

`every` 模式为了赶在"尾巴渲染"之前把事件备好，改到了**轮次开始**发布 —— 但一轮可能跑好几分钟。
于是贴纸在用户还没看到回复时就出现、又消失，等人读到回复时什么都没有。

**修法：轮末刷新。** `agent/turn-stopping` 时用**同一张图再发一次**（新的时间戳、新的 seq）：

- 客户端拿到刷新后 2.5 秒触发兜底 → 正好落在"回复刚写完"；
- 气泡若先认领，兜底看到待绑定槽空了会**自动收起**，不会出现两张；
- 仓里对"同一 id 已经显示过"做去重，刷新的那条不会重复弹出。

另外给兜底加了**几何自报**（`fallback-rect`：坐标/尺寸/视口/页面可见性）——
万一"日志说显示了但人看不见"，下一步就能直接判断是不是布局问题，而不用再猜。

> 顺带一条经验：**"什么时候显示"和"显示什么"一样是需求**。前四个 bug 都在解决
> "能不能显示"，第五个才是"用户看不看得见"。
